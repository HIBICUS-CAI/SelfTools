# FastReplacer

指定フォルダ内の全ファイルを UTF-8 テキストとして扱い、文字列を高速に検索・置換するコマンドラインツール (Windows x64 / C++20)。
数 GB 以上の巨大ファイルを想定し、速度を最優先にしている (メモリ使用量は二の次)。

## 使い方

```
FastReplacer <フォルダ> -f <検索> [-f <検索2> ...] -r <置換> [オプション]   置換モード
FastReplacer <フォルダ> -f <検索> [-f <検索2> ...] -s [オプション]          検索のみ (レポート出力)
```

| オプション | 内容 |
|---|---|
| `-f, --find <text>` | 検索文字列 (必須・複数指定可。全て同じ置換文字列に置き換える) |
| `-r, --replace <text>` | 置換文字列 (1 つのみ。空文字列 `""` で削除) |
| `-s, --search-only` | 検索のみ。結果をレポートファイルに書き出す |
| `-c, --match-case` | 大文字/小文字を区別する (既定: 区別しない) |
| `-w, --whole-word` | 単語単位で検索する (既定: 無効) |
| `-R, --recursive` | サブフォルダも対象にする (既定: 直下のみ) |
| `-e, --escape` | `\\ \n \r \t \0 \xHH \uXXXX \UXXXXXXXX` を解釈する |
| `-x, --context` | レポートに前後の文脈を出力する (既定: 位置のみ) |
| `-o, --report <path>` | レポートのパス。既定はカレントの `FastReplacer_report_<日時>.txt` (置換モードは指定時のみ出力) |
| `-t, --threads <n>` | スレッド数 (既定: 論理コア数) |
| `--direct` | OS キャッシュを経由せず RAM へ直接読み込む (後述。既定はメモリマップ) |

- 短いオプションはまとめて指定できる (例: `-cwR`)。値を取るオプション (`-f -r -o -t`) をまとめた場合、
  値は後続の引数から順に取る (例: `-rc 新`、`-cfr 旧 新`)。
- 長いオプションは `--find=値` の形式も可。

終了コード: `0`=成功 / `1`=一部ファイルでエラー / `2`=引数エラー

※ cmd/PowerShell では `"D:\data\"` のように `\"` で終わる引数はクォートが壊れるため、末尾の `\` を付けないこと。

### 例

```bat
FastReplacer D:\logs -f "ERROR" -scw -o D:\report.txt
FastReplacer D:\data -f "旧名称" -f "旧称" -rR "新名称"
FastReplacer D:\data -f "\r\n" -er "\n"
FastReplacer D:\logs -f "timeout" -f "refused" -sx
```

### レポート (検索モード)

UTF-8 (BOM 付き)。一致ごとに 1 行。既定は位置のみ:

```
=== D:\logs\a.txt  (3 件: #1=2 #2=1, 3.20 GiB)
  L120:C5  @48213  #1
```

`-x` 指定時は文脈も出力する:

```
  L120:C5  @48213  #1  前の文脈【一致】後ろの文脈
```

`L` = 行番号 (LF 区切り), `C` = 行頭からの文字数 (コードポイント, 1 始まり), `@` = バイトオフセット (0 始まり),
`#` = 一致した検索文字列の番号 (`-f` が複数のときのみ)。
文脈は前後 100 バイトまで。制御文字や不正な UTF-8 は `\r` `\xHH` のようにエスケープ表示する。

## 照合仕様

- バイト列として照合する (BOM・改行コードは変換しない。Unicode 正規化もしない)。不正な UTF-8 バイトはどの文字とも一致しない。
- 一致は先頭から貪欲・重なりなし (並列処理でも逐次処理と完全に同じ結果になる)。
- **複数の `-f`**: 最も左の一致を採用。同じ位置で複数一致した場合は最長のもの (同じ長さなら先に指定したもの) を採用する。
- **大小区別なし (既定)**: Unicode 単純ケースフォールディング (CaseFolding.txt の C+S) で同一視する。
  `Ａ`/`ａ`、`Σ`/`σ`/`ς` なども一致。ただし ASCII と非 ASCII 同士は一致させない (`K`(U+212A)≠`k`, `ſ`≠`s`)。
- **単語単位**: パターンの先頭 (末尾) が単語文字の場合、その直前 (直後) が単語文字でないこと。
  単語文字は .NET 正規表現の `\w` と同じ `[\p{L}\p{Mn}\p{Nd}\p{Pc}]`。日本語の漢字・かなも単語文字として扱う。

## 置換の動作

- 一致があったファイルのみ、同じフォルダに `<元ファイル名>.frtmp` を書き出してから `ReplaceFileW` で置き換える
  (元ファイルの属性・ACL・作成日時を維持)。途中で失敗しても元ファイルは壊れない。
- 中断 (Ctrl+C 等) で `.frtmp` が残った場合は削除してよい (`.frtmp` は処理対象から除外される)。
- 一致の無いファイルは一切書き換えない。

## 高速化の要点

- **ファイル単位のパイプライン**: 「読み込み」「検索」「出力 (レポート/置換書き込み)」を別々に進め、
  ファイル A の書き出し中にファイル B の読み込み・検索を行う。各段はファイル順を保つので結果・出力順は逐次処理と同じ。
  同時に保持するファイルは最大 3 つ。
- **読み込み (既定)**: メモリマップ + `PrefetchVirtualMemory` による先読み。OS のファイルキャッシュが効くので、
  キャッシュ済みのファイル (直前に検索した・コピーしたばかり等) はメモリ速度で読める。
- **読み込み (`--direct`)**: ファイル全体を RAM に読み込む。`FILE_FLAG_NO_BUFFERING` (OS キャッシュを経由しない) の
  非同期読み込みを 8 MiB × 16 本同時に発行し、読み終わった範囲から順に検索を始める。
  RAM の使用上限は起動時の空き物理メモリの 80%。超えるファイルや確保に失敗したファイルはメモリマップで読む。
  - 効果があるのは**キャッシュに載っていない巨大ファイルを高速 SSD から初回に読む場合のみ**。
    非バッファで開いた時点で OS がそのファイルのキャッシュを書き出して破棄するため、キャッシュ済みでもディスクから読み直しになり、
    それ以外の場合は既定より遅くなる (直後に既定モードで処理する場合も再びディスク読みになる)。
- 検索はファイルを 32 MiB 単位に分割して全スレッドで並列実行。AVX2 (非対応 CPU は SSE2) で、
  パターン中の出現頻度が低い 2 バイト位置を同時に比較して候補を絞り込む。複数の `-f` は 1 MiB 窓ごとに交互に進めてキャッシュ効率を保つ。
- 置換出力は 32 MiB ブロックを並列に直接生成し、`FILE_FLAG_NO_BUFFERING` で先頭から順に書き込む
  (キャッシュを汚さず、NTFS の VDL ゼロ埋めも発生しない)。
- レポートも並列に整形しながら順に書き出す。

## ビルド

- Visual Studio: `FastReplacer.vcxproj` (v143 / x64 / C++20 / `/utf-8`)
- CMake: `cmake -S . -B build && cmake --build build --config Release`
- MinGW (クロス): `x86_64-w64-mingw32-g++-posix -std=c++20 -O2 -municode -static -o FastReplacer.exe src/*.cpp`

`src/UnicodeData.inc` は `python tools/gen_unicode.py` で生成 (Python の unicodedata を使用)。

## テスト

```
python tests/test_fastreplacer.py <FastReplacer 実行ファイル> --cases 300
```

ランダムなテキスト (日本語・ギリシャ文字・特殊ケース文字・不正 UTF-8・CRLF を含む) の複数ファイルに対し、
チャンクサイズ 1 バイト〜1 MiB、スレッド数 1〜8、複数の `-f` (同位置で競合するものを含む)、オプションのまとめ指定、
RAM 読み込み/メモリマップ/メモリ上限による混在で、Python の素朴な参照実装と検索結果 (行・列・オフセット・番号) と置換結果を突き合わせる。
`tests/bigfile_test.py` は 4 GiB 超ファイルでの検証。
